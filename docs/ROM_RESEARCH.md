# 한국어 골드 → 디자인몬: ROM 연구 01

2026-09-16. 목표는 원본 ROM을 실제 분석·수정하는 작업 기반 마련이다. 첫 실험은 스타터 세 종의 종 이름 교체이며, 완성 게임이나 전체 디컴파일 결과가 아니다.

## 식별과 근거

제공 ZIP은 2,097,152바이트 `Pokemon Gold.gb`, Windows 에뮬레이터, 설정 파일 등을 포함한다. 에뮬레이터 EXE는 실행하지 않았다. ROM만 읽었으며 저장소에는 넣지 않았다.

| 항목 | 직접 측정한 값 |
|---|---|
| SHA-1 | `c0ff3999e1093e1af59ef3eea3f1bfd7c1f18a65` |
| SHA-256 | `9c273e86e6120c6a038160ccb0153b8b20425b84fc08a496281c1d1bcac492f6` |
| 헤더 문자열 0134–0142 | `POKEMON_GLDAAUK` |
| CGB 플래그 | `C0` |
| 카트리지 종류 | `10`: MBC3 + 타이머 + RAM + 배터리 |
| ROM / RAM 크기 코드 | `06` / `03`: 2 MiB / 32 KiB |
| ROM 뱅크 수 | 128 × 16 KiB |
| 헤더 / 전체 체크섬 | 모두 정상 |

[Pan Docs](https://gbdev.io/pandocs/The_Cartridge_Header.html)의 구조 정의를 적용했다. 파일 확장자 `.gb`만으로 DMG 전용이라고 판단하면 안 된다.

SHA-1은 [한국어 디스어셈블리](https://github.com/Narishma-gb/pokegold-kr/blob/f4496dda3003ccc5fc26f2757171a3b111e65307/README.md)의 Korean Gold 기준 해시와 일치한다. 참조 소스 커밋은 `f4496dda3003ccc5fc26f2757171a3b111e65307`. 이 프로젝트 자체는 WIP다. 영문 pret/pokegold의 주소를 한국판에 그대로 적용하지 않았다. 공개 소스는 별도 임시 폴더에서 읽었고 해당 게임 소스와 에셋을 이 저장소에 복사하지 않았다.

## 실제 확인한 이름 테이블

참조 `PokemonNames` 심벌은 ROM `6C:4C4A`. 스위칭 뱅크의 파일 오프셋은 `bank × 0x4000 + (CPU 주소 - 0x4000)`이므로 테이블 시작은 `0x1B0C4A`다. 종 ID는 1부터 시작하며 레코드는 **10바이트**다. 한국어 글자는 2바이트여서 최대 5글자를 담는다. 남는 바이트는 종료 코드 `50`으로 채운다.

| ID | 이름 | 파일 오프셋 | 원본 10바이트 | 수정 10바이트 |
|---|---|---|---|---|
| 152 | 치코리타 → 일러몬 | `1B1230` | `0901093A043E09885050` | `079F03DF049350505050` |
| 155 | 브케인 → 코딩몬 | `1B124E` | `054A0929079E50505050` | `093A0369049350505050` |
| 158 | 리아코 → 타이포몬 | `1B126C` | `043E06C6093A50505050` | `0988079C0A2704935050` |

표의 원본 바이트는 실제 입력 ROM과 대조했다. 세 이름은 실험용 설정이며 기존 웹 프로토타입의 일러몬·코딩몬 명칭을 참고했다.

인코딩은 UTF-8이나 EUC-KR이 아니다. `일=07 9F`, `러=03 DF`, `몬=04 93`, `코=09 3A`, `딩=03 69`, `타=09 88`, `이=07 9C`, `포=0A 27`. 참조 문자표의 `def_kr_table 10`은 10진수이므로 `포`의 첫 바이트는 `10`이 아니라 `0A`다. 패처와 테스트에 이 차이를 반영했다.

## 엔진에서 검증한 호출 경로

1. `wNamedObjectIndex` (`D20E`)에 종 ID를 넣는다.
2. 원본 `GetPokemonName` (`00:365B`)를 CPU에서 실행한다.
3. 함수는 이름 테이블을 읽고 `wStringBuffer1` (`D036`)에 10바이트 및 종료 코드 1바이트를 쓴다.
4. 원본 `PlaceString` (`00:0F6F`)을 호출해 원본 한국어 글꼴로 출력했다. `wTilemap=C3A0`, `DelayFrames=00:033C`도 이 실험에서 사용했다.

검증 스크립트는 부팅 후 저장한 에뮬레이터 상태를 매 테스트 전 복원한다. 테스트용 RAM 코드와 스택을 주입해 실제 ROM 함수를 호출하고 반환 결과를 비교한다. 한글 표시 확인 이미지는 **디버거 표시 실험**이다. 실제 메인 메뉴를 변경하거나 새 게임 이벤트를 구현한 것이 아니다.

## 결과와 검증 범위

- 기본 패치 결과 SHA-256: `d7e66cf917280e2046d1af242395ba5379e5f05f592f4702c56c7542396d549c`.
- 수정 23바이트. 이름 레코드와 전체 체크섬만 변경. 헤더 및 전체 체크섬 정상.
- IPS를 원본에 적용한 결과가 수정 ROM과 바이트 단위로 일치.
- Python 단위 테스트 9개 통과: 문자 인코딩, 체크섬, 잘못된 원본 차단, 수정 범위, IPS 일반/RLE/긴 레코드/손상 입력.
- PyBoy 2.7.0에서 원본과 수정본을 각각 1,140프레임 부팅. 메뉴 픽셀 동일.
- 게임 CPU 이름 조회 3개 모두 통과. 한국어 렌더링 이미지 직접 확인.
- Chrome / Playwright에서 로컬 HTML 확인. 브라우저 ROM·IPS가 Python 출력과 동일. 잘못된 글자와 수정 ROM 입력 차단, 390px 모바일 가로 넘침 없음, JS 오류 없음.

미검증: 실제 스타터 획득 과정, 전투 전 구간, 기존 세이브 호환성, 자연스러운 게임 플레이 전체. 세이브에 이미 기록된 닉네임과 대사에 하드코딩된 기존 이름은 이 패치로 바뀌지 않는다. 스프라이트·맵·음악·전투 규칙은 교체하지 않았다. 전체 디자인몬 게임은 후속 개발 범위다.

다음 작업은 새 게임에서 스타터 획득까지 추적해 테이블 참조와 대사 내 고정 문자열을 구분한 뒤, 포인터·압축 방식을 검증한 스프라이트 하나를 교체하는 것이다.
